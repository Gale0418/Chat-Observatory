# INC-001｜控制面板污染 YouTube 虛擬留言清單

- 狀態：Resolved
- 日期：2026-08-15
- 對應任務：CO-H5

## 摘要與影響

為避免控制面板遮住聊天室，先前將 `#chatobs-control-panel` 直接 `prepend` 到 YouTube 的 `#items`。使用者實機回報留言順序異常，且控制面板隨聊天室捲動消失。

## 症狀與重現

- `#items` 的第一個直接子節點不是 YouTube renderer，而是擴充功能面板。
- 捲動聊天室後，`position: sticky` 面板會離開可視範圍。
- YouTube 的虛擬清單可能將非 renderer 子節點納入索引／回收計算，造成畫面順序不可靠。

## 根因

把第三方 UI 注入 YouTube 擁有的虛擬清單資料容器，破壞其「直接子節點皆為聊天項目」的不變條件；同時將固定工具列的生命週期錯綁到內部捲動容器。

## 拒絕方案

- 只提高 `z-index`：無法修復留言子節點污染或 sticky 捲走。
- 把面板移到 `#item-scroller`：仍會介入 YouTube 的虛擬捲動尺寸與回收計算。
- 以 CSS `order` 重排：只改視覺，不修 DOM 契約。

## 最終修正

- 面板留在 `body` 的擴充功能固定層，使用 `position: fixed`。
- 以 `ResizeObserver`／resize fallback 同步 `--chatobs-panel-offset`，讓聊天室清單依展開／收合高度保留空間。
- `#items` 只監看 renderer，不再插入或搬移面板。
- fixture 改為接近真實 YouTube 的內部 scroller，新增留言順序回歸測試。

## 驗證證據

- `npm run verify`：37/37 通過。
- `npm run build:extension`：發布 ZIP 重建成功。
- Chrome 430×500 與 1280×800：捲動前後面板 `top: 8px`；展開／收合時面板與 scroller 重疊 0px；水平 overflow 0；三則留言 DOM 順序不變。

## 升格教訓

- CL-001：不得把擴充功能自訂 UI 插入第三方虛擬清單的資料子節點。

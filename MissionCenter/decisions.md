# 決策

- 2026-07-17：產品採純本機、無後端架構；第二台聊天室電腦直接開啟同一場 YouTube 直播並執行擴充功能。
- 2026-07-17：核心單一目的為「大字監看與本機 TTS」，不加入帳號、雲端配對、多平台或 OBS 控制。
- 2026-07-17：維持原生 JavaScript/CSS，避免為四檔小型擴充功能導入前端框架。
- 2026-07-17：介面方向採深色霧面、高對比、分段模式切換，優先照顧遠距離閱讀與直播中快速操作。
- 2026-08-12：專案整理採最小安全變更，不全面搬移既有結構；保留 `store-assets/`、`MissionCenter/` 與 `output/` 的發布／驗證證據，僅移除明確系統垃圾與無引用的過期 QA 副本。
- 2026-08-12：發布流程改為逐檔 SHA-256 核對並驗證 ZIP 白名單，避免 `dist/` 與根目錄原始碼再次失去同步。
- 2026-08-12：CodeRabbit 未執行，因未取得把程式碼上傳至外部審查服務的明確授權；正式 Completion Critic 未派送，因沒有獲准的總額／席次／工具／時間預算。本輪改由多支本機專家工作線、Antigravity 與 Chrome 實機證據交叉檢查，H5 保留 Review。
- 2026-08-12：全面 hardening 採三波 TDD：先修 URL／MV3／發布邊界，再修 TTS／設定／DOM 重連，最後處理 teardown／無障礙／跨平台工具與 Chrome 實機驗收；每波都必須可獨立回滾。
- 2026-08-12：依 Chrome 官方文件，service worker 狀態放入 `chrome.storage.session`，不使用全域變數當真相、不以 keep-alive 阻止休眠，也不新增 `alarms` 權限處理 4.5 秒短提示。
- 2026-08-12：線上語音 `localService=false` 不符合純本機核心承諾；只提供明確本機 voice，沒有可用本機語音時停用朗讀，不退回來源不明的系統預設。
- 2026-08-12：商店截圖採安全 staging；兩張新圖都成功並通過 1280×800 PNG 驗證後才逐檔替換正式素材，Chrome 失敗時保留上一版。
- 2026-08-12：拒絕引入前端框架、DOMPurify、offscreen TTS、後端與新權限；跨平台工具只做最小 Chrome 探索與平台限制說明，不引入影像處理函式庫。
- 2026-08-12：視覺升級採 `taste-skill` 的既有產品 redesign 診斷流程，方向定為暖黑石墨底、珊瑚單一重點色、緊湊但可呼吸的「直播導播控制台」；圓角、表面、陰影與互動狀態統一由 CSS token 管理。
- 2026-08-12：不採 `gpt-taste` 的 AIDA、大型 Hero、Bento 與 GSAP 動畫，因 520px 擴充功能控制面板屬工具型介面；不安裝外部技能、字型、素材或前端依賴，只乾淨室採納一般設計原則。
- 2026-08-12：畫風系統擴充為「熔岩、極光、紙墨」三套語意 token；共用同一份元件 CSS 與設定生命週期，不複製版型。每套維持單一重點色，主題值經白名單清洗並透過既有 `storage.local` 持久化與跨視窗同步。
- 2026-08-12：依使用者決定將畫風總數固定為四套，正式規格為熔岩、極光、紙墨、星夜；除色票外，同時以面板材質、圓角尺度、字體、頭像輪廓與聊天室卡片形狀建立顯著差異，但仍共用元件結構與可及性規則。
- 2026-08-14：MissionCenter 遷移至最新版單一任務生命週期。`tasks.md` 繼續作為唯一狀態與排序來源；`project.md`、`progress.md`、`brief.md`、`working-set.md` 與 HUD 改由同步工具產生，避免手寫摘要再次分叉；已移除完成相容期的舊 `focus.md`。
- 2026-08-14：移除任務語意重疊而不抹除歷史證據：YTCE-M1 僅代表已驗證的核心與介面、YTCE-H5 統一承接新版 Chrome 實機驗收、YTCE-P1 收斂為已完成的本機商店素材與文件草稿、YTCE-P2 獨立追蹤仍缺的正式聯絡資訊，YTCE-V1 只負責快照與收尾。
- 2026-08-14：進度估算只讓可交付的葉節點承擔估時；Epic 與含子任務的聚合列設為 0，避免多層任務重複加總造成虛假進度。
- 2026-08-14：新版 `snapshot_mission_center.py` 在目前系統 Python 因 `Path.write_text(newline=...)` 不相容而無法寫檔；本次依相同 canonical facts 與 schema 產生 checkpoint，未修改全域技能程式，並以最新版 doctor 驗證格式。
- 2026-08-14：四套畫風的範圍由控制面板擴大為整個聊天室 canvas、訊息卡、頁首與輸入表面；只鎖定已知 live_chat 容器，不使用全域後代 selector，以保留 emoji picker 與互動控制。設定面板改為 `#items` 內的 sticky 設定列，展開時推動訊息、收合時與訊息同寬，不再以 fixed 浮島遮住聊天室。
- 2026-08-14：以 Impeccable 4.0.4 作為既有四主題的 polish／驗證參考，不安裝其 hooks 或新增依賴，也不接受會抹平「熔岩、極光、紙墨、星夜」美術差異的通用規則；採納語意 token、瀏覽器表面、明確狀態、CSS 幾何圖示與實際渲染複驗，維持「精修而非重設計」。
- 2026-08-15：因實機發現留言順序回歸，撤銷「將設定列插入 `#items`」的實作決策；控制面板改由 `body` 自有固定層持有，使用實測高度 offset 縮減聊天室捲動區。第三方虛擬清單的資料容器只允許觀察 renderer，不注入自訂 UI。
- 2026-08-15：多語 TTS 採單一 FIFO 上的逐則 voice 路由，不依語言拆分佇列或拆分混合句；auto 只從 `localService=true` 清單依 script 與有限文字提示保守配對，無法判定時退回使用者預設 voice。固定 voice 消失則停住並提示，不靜默改用其他或來源不明的系統預設。
- 2026-08-15：Web Speech voice 沒有評分或音質欄位，因此介面只稱「推薦」；排序採可解釋的社群偏好與 metadata heuristic，不捏造星等。遠端 Google／第三方 TTS engine 不納入純本機推薦，除非未來另設明確 opt-in、權限與隱私揭露。
- 2026-08-15：四主題顯示規格改為紅黑綠黃順序的赤曜／玄曜／翠曜／金曜；底層 `ember`／`aurora`／`paper`／`starlight` ID 保留以維持既有儲存相容。視覺允許高調電競漸層、材質紋理與小面積流光，但動畫只作用於飾線、內框與啟用控制，並由 `prefers-reduced-motion` 完整停用。
- 2026-08-15：四主題的宇宙背景採本機封裝 JPEG，不依賴遠端素材；只透過 `web_accessible_resources` 暴露給正式 `https://www.youtube.com/live_chat*`。圖片只鋪在面板與聊天室外層畫布，留言虛擬清單保持原 DOM 與透明內層；亮色文字用近黑描邊，深色啟用文字改用主題亮色反描邊。
